（二）自定义环境：Miniforge3创建Python虚拟环境
集群内置miniforge3/25.11.0-1，可快速创建虚拟环境。
完整示例操作命令
# 1. 进入~/run目录
cd ~/run
# 2. 加载miniforge3内置环境
module load miniforge3/25.11.0-1
# 3. 创建虚拟环境
conda create --name py37 python=3.7
# 4. 查看已创建的所有conda环境
conda env list
# 5. 激活虚拟环境
source activate py37
# 6. 激活后安装第三方包
pip3 install XXX
# 7. 查看当前环境已安装包
pip3 list
# 8. 退出当前conda环境
conda deactivate

（二）推荐方式：sbatch批处理提交作业（正式运行，后台执行）
特点
- 终端断开后作业仍在后台运行，任务完成后自动停止计费；
- 支持脚本配置参数，资源利用更规范，优先使用此方式。
步骤1：编写作业运行脚本（以gpu_h200队列为例，命名为run.sh，存于~/run）
脚本为bash格式，第一行指定解释器，通过#SBATCH配置资源参数，所有路径使用~/run内的相对/绝对路径，提供2类常用示例：
示例：Python程序运行脚本run.sh
#!/bin/bash
#SBATCH --gpus=1        # 申请1块GPU卡，自动分配12CPU核+252GB内存
#SBATCH -p gpu_h200    # 指定队列：gpu_h200

# 加载 miniforge 并正确初始化 conda
module load miniforge3/25.11.0-1
source /data/apps/miniforge3/25.11.0-1/etc/profile.d/conda.sh
conda activate /data/home/scwb310/run/conda_envs/XXX

# 进入作业运行目录
cd /data/home/scwb310/run

# 运行 Python 程序
python test.py
步骤2：提交作业
sbatch -p gpu_h200 --gpus=1 /data/home/scwb310/run/run.sh
提交成功后会返回作业ID，用于后续查看/取消作业。
（三）调试方式：salloc申请资源（最好仅用于测试，正式运行还是用“（二）推荐方式”）
核心特点
- 申请后直接登录计算节点，实时调试程序；
- 终端断开则任务中断，任务完成后需手动取消，否则持续计费，仅用于程序验证，正式运行用sbatch。
操作命令
# 申请GPU资源，指定队列和卡数
salloc -p gpu_a800 -N 1 --gres=gpu:4 --qos=gpugpu
# 申请成功后，终端会返回计算节点名（示例：d1n42a13g01），登录该节点
ssh 计算节点名 # 示例：ssh d1n42a13g01
# 进入环境
module load miniforge3/25.11.0-1
source activate XXX
python train.py
nvidia-smi # 查看GPU利用率
# 调试完成后，必须手动取消作业（否则持续计费）
scancel 作业ID # 作业ID通过parajobs命令查询
四、作业管理：查看/取消作业
1. 查看作业状态
parajobs
输出字段
字段
说明
JOBID
作业ID，唯一标识，用于取消作业
PARTITION
作业运行的队列名
STATE
作业状态：R(运行中，计费)/PD(排队)/CD(完成)/F(失败)/CG(正在退出)
NODELIST
运行中的作业显示计算节点名，排队中的作业显示排队原因
TRES_ALLOC
分配的资源（CPU/内存/GPU）
GPU利用率
显示每块GPU的利用率、显存使用情况，0%表示未正常调用GPU
2. 取消作业（运行中/排队中均可取消）
scancel 作业ID # 示例：scancel 6（取消作业ID为6的作业）
注：salloc调试完成后、作业运行异常时，必须及时取消作业，避免无效计费。
五、注意事项
1. 登录节点（In01）仅做编辑/编译/脚本编写，计算节点仅运行计算任务；
2. 所有计算相关操作（软件安装、数据存放、作业运行）均在~/run目录执行，避免家目录配额超限；
3. 仅R(运行中)状态计费，salloc调试后必须手动取消作业，sbatch作业完成后自动停止；
4. 软件安装、脚本编写、资源申请遇到问题，直接在微信服务群@客服协助。
5. 本文档只叙述了正常执行过程和一些注意事项，例如跨节点任务执行等详细命令介绍见下方PDF。
